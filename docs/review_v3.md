# 数据化大脑 · 第三轮全方位对抗性审查（针对交付包本身）

**对象**：第二轮交付的两个 zip（脱敏版 / 未脱敏版），以及修复动作自身引入的缺陷。
**日期**：2026-09-28
**方法与前两轮的差别**：前两轮审的是工作树；这一轮先审**交付容器本身**
（zip 条目、权限位、编码、CRC），再从**全新解压态**重跑全部证据，
最后覆盖前两轮没碰的面：脱敏映射的代数性质、外部数值污染产物、
HTTP 边界行为、口令在日志里的生命周期。
**证据标准**：与前两轮一致 —— 只认沙盒里真实跑出来的结果。
子代理先报的结论，一律在我自己的副本上独立复现后才写入本报告。

## 1. 容器层审查

本轮的审查对象就是**上一轮已经交付出去的那两个 zip 本体**，
再对新一轮打包产物复跑同一套检查。

对已交付包（`databrain_{public,private}_20260928.zip`）：

- 40 个条目：无 `..`、无绝对路径、无反斜杠、无 create_system 异常；
  非 ASCII 文件名全部带 UTF-8 标志位。
- 逐条目 `zf.read()` 全量解压：零 CRC / 读取错误。
- public 包内 `.private` 命中数 **0**；private 包内 `.private/` 四个文件齐全，
  与母本 md5 一致（`real.full.json` = `810fada6…`，
  `legacy/real.json` = `1ef58a0f…`）。
- 两包 `__pycache__` / `*.pyc` 命中数 **0**。
- 真实对端人名（5 位）在两包内命中数 **0**；沙盒绝对路径命中数 **0**。

对新一轮两个包（`databrain_{public,private}_20260928_r3.zip`，
36 / 42 个常规文件）：同一套检查全部通过，且加了下面两条新判据 —— 
权限位必须恰为 `0644`、私有语料指纹必须零命中（见 N15）。

**容器层这轮抓到一条我自己的打包缺陷**：第二轮交付的两个 zip 里
`README.md` 的权限位是 `0600`（其余全部 `0644`）。成因是编辑工具链
（`Edit`/`Write`）在某些路径上保留了 restrictive 模式，而我打包时用的是
`zip -r`（忠实携带源树权限位），Round-2 的容器审计脚本只检查了
"是否存在异常位"里的 setuid/可执行那一类，**没把"数据文件不该是 0600"
列进判据**，所以两轮都放过了它。
后果对开源发布是实际的：解包后 `README.md` 不可被其他用户读，
CI 里以别的用户跑 `cat README.md` 直接 Permission denied。
现在判据改成"**全部常规文件必须恰为 0644**"，两侧都修：
`chmod 644` 归一化 + 审计脚本断言。第三轮两个包实测 non-644 列表为空。

**根因这轮才真正确认**：查母本 `src/` 时发现权限位本来就是混的 ——
`README.md` 是 `0600`、十来个文件是 `0666`、其余 `0644`。
也就是说这不是打包脚本随机抽到的个例，而是**编辑工具链写文件时的默认
umask 行为**，会随每次改动继续漂移。所以现在的固定动作是打包前
两条一起跑：`find . -type f -exec chmod 644 {} +` 与
`find . -type d -exec chmod 755 {} +`，再由 `release_check.py` 兜底断言。
同一轮里还顺手验了一件事：`chmod` 只改元数据，
归一化前后 `real.redacted.json` 的 md5 仍是 `53b6ee5a…`、
`server.py` 与包内副本逐字节一致 —— 权限修复没有夹带内容改动。

打包前另外抓到的两处发布污染（已在上一轮收尾时修掉，此处复述以便追责）：
探针在包内运行会生成 `.private/`，需在打包前剔除；
文档里曾残留一个**我合成测试用的假名**（非任何真实对端）与沙盒绝对路径，
现已统一改为 `测试甲` 这类一眼可辨的占位名。

## 2. 新发现与修复

### N6 · 脱敏替换的级联碰撞（严重 · 身份合并）

**缺陷**：`_redact()` 原先对每个别名依次执行 `s.replace(old, new)`。
替换写进字符串后，**新写进去的代号会再次被后续规则匹配**。

**实测复现**（构造语料里真有两个的人分别叫 `P2` 与 `P20`）：

```
alias = {'P2': 'P1', 'P20': 'P2', '阿澈': 'P3'}
脱敏前：3 个不同的人
脱敏后：['P1', 'P1', 'P3']        ← P20 → P2 → P1，两个人并成同一个代号
主题键：'T:P20|warm|日常' → 'T:P10|warm|日常'   ← P2 被从 P20 内部挖走
```

这与第二轮的 B12 是**同一个缺陷类**（清洗/映射把不同身份合并），
只是从"姓名清洗"这一层挪到了"代号映射"这一层。
前缀包含同理：短名 `李明` 先替换会把长名 `李明华` 切碎。

**为什么前两轮没抓到**：第二轮的递归清洗已经解决了"漏字段"，
而"逐别名依次替换"在当时是唯一实现，探针的夹具人名
（阿澈/老周/K./Momo/奶奶/室友）互不为子串，级联路径根本没被触发。

**修复**：新增 `_make_sub()`，用**一次性交替正则**做单趟同时替换 ——
全文只扫一遍，替换结果不再参与匹配；候选按长度降序排列，
保证 `李明华` 优先于 `李明`。
顺带删掉 events / persons / themes / episodic / chains / timeline / recon_log
六处逐字段映射，统一交给那一次递归清洗：代码更少，覆盖面更大。

**修复的修复**（自审抓到两处我引入的边界问题）：
- 空别名表时 `_make_sub` 返回 `None`，`scrub()` 调用 `None(s)` 直接崩 →
  改为返回恒等函数，并过滤空字符串键（空键会让交替正则退化成每字符都匹配）。
- 交替正则的候选顺序：`sorted` 需按 (-len, name) 稳定排序，
  否则同一长度候选的匹配优先级不确定。

**回归**：`P-CASCADE`（三人生成三个不同代号）。
**形式化验证**：400 次随机抽样构造"人名互相对齐代号命名空间"的别名表，
注入性失败次数 —— 老实现 **51/400**，新实现 **0/400**；
另一轮 600 次走完整 `_alias_of + _redact` 路径，非注入试验本数 **0**。
**输出漂移**：正常演示语料下 `real.redacted.json` md5 仍为 `53b6ee5a…`，
与上一版逐字节一致。

**已知局限（不算缺陷，记为开放风险）**：代号以"人名的任意子串"形态匹配，
所以会**过度脱敏** —— 若某人叫 `李`，文本里的"李白"会变成"P1白"。
实测：`'他去了李白的故乡'` + `{'李':'P1'}` → `'他去了P1白的故乡'`。
这是替换式脱敏的固有代价；方向是过脱敏而非漏脱敏，安全侧不倒挂，
但发布说明里应当写明：人名越短、越常见，产物可读性损失越大。

### N7 · 外部数值污染产物（严重 · 浏览器侧崩盘）

**缺陷链**：`people.json` 里用户手写的 `weight` 是外部输入，被直接乘进事件强度
`inten * (0.75 + 0.05 * weight)`。填 `-Infinity` 时（Python 的 `json.load`
默认**接受**这个非标准字面量）intensity 变成 `-inf`，
一路穿过引擎、写进**发布版** `web/real.redacted.json`，产物里出现 `-Infinity`。

**实测后果**：

```
浏览器：JSON.parse → "No number after minus sign in JSON at position 61887"
        → viewer 整个白屏，没有任何提示
Python：json.load → 正常读回（因为 Python 允许 NaN/Infinity）
生成期：无任何 warning、无失败退出码
```

这是典型的**生成期静默、消费期崩盘**：错误只在你把产物交付出去之后才暴露，
而且暴露的是最要命的那一半（发布版）。前两轮所有探针都跑在 Python 侧，
"产物在浏览器里能不能打开"这件事从来没被验证过。

**修复（两道边界）**：
1. corpus 入口：要求 `weight` 有限、非数值回落 0、夹紧到 `[0, 10]`
   （量纲本来就是 0~10，见第二轮 N5）；intensity 结果再校验一次有限性。
2. 序列化出口：`_write()` 与 server 的 `_send()` 统一 `allow_nan=False` ——
   任何来源的脏数值只能在写盘/响应这一道炸出来，
   不可能带着坏产物去发布。`_write` 会带上具体文件名的明确报错。

**实测验证**：
- 脏 weight 七种取值（`-inf / nan / 'abc' / None / 1e999 / 999999 / -50`）
  全部落为有限且在 `[0,1]` 内。
- 服务端注入一个含 NaN 的产物后请求 `/api/real`：返回 **HTTP 500 + 明确错误文本**
  （`Out of range float values are not JSON compliant: nan`），
  **进程存活**，随后 `/api/health` 仍 200，日志无 traceback。
- `P-NFINITE` 探针覆盖上述两类断言。
- 正常演示语料：三份产物 md5 全部不变。

### N8 · 前端诊断串的潜在汇点（纵深防御 · 当前不可利用）

`renderDiag()` 把 `failures` / `warnings` / `hormone_extremes` 的键直接插进
`innerHTML`。逐条查了来源：这些串由引擎常量与 `b.id` 拼成，
合成场景的 `b.id` 来自 seed 驱动的场景名，真实语料的 `b.id` 里的 subject
已被脱敏为 `P#` —— **当前打不出去**。

但判"当前不可利用"不等于判"设计正确"：同一处汇点一旦将来嵌入语料可控字段，
就是下一个存储型 XSS。按第二轮 A2 的同一标准补 `esc()`，成本零，
并把判断依据写进代码注释而不是留白。诚实定性：**纵深防御，非漏洞修复**。

### N9 · 口令落日志（中 · 子代理先报，我在副本上复现）

token 支持 `?token=` 传入，于是明文出现在 HTTP 请求行里，
而请求行正是要被 access log 写进 stderr 的东西
（终端回滚、`nohup.out`、任何日志采集都能看到口令）。

实测：`GET /nope?token=s3cr3t` → 日志出现 `"GET /nope?token=s3cr3t HTTP/1.1" 404`。

**修复**：日志输出前过 `_mask_secrets()`，掩掉 `token / access_token / auth / api_key / key`
的参数值，只改日志视图、不动真实请求。

**修复自身的绕过（我复现后又抓到的）**：第一版只按**原始文本**匹配字面参数名。
`?%74oken=xxx`（把参数名的 `t` 百分号编码）**照样能通过鉴权**
—— 因为 `parse_qs` 会先解码参数名；而日志里那条请求行不含字面 `token`，
正则匹配不到，于是口令明文落进日志。实测确认（该请求返回 200，日志含明文）。

补漏后：对解码文本再掩一遍，并用 `_AUTH_TOKEN` 明文兜底替换。
实测四种编码/大小写变体（`token=` / `%74oken=` / `%54OKEN=` / `token=%733cr3t`）
+ `api_key=` 全部日志无明文，口令泄露计数 0，
同时鉴权行为不变（正确口令 200、错误口令 401、header 200）。

### N10 · 口令比较非常量时间（低）

`==` 的短路行为在 `DATABRAIN_HOST=0.0.0.0` 部署下是可测量的字节前缀旁路。
默认只监听 127.0.0.1，所以这是**纸面问题**，但 README 明确支持放到局域网，
所以补上。

**踩到的坑（记下来免得重演）**：第一版写成 `hmac.compare_digest(str, str)`，
非 ASCII token 会抛 `TypeError` → 变成 **500**，等于修旁路时新引入一个崩溃点。
改为两侧 `encode('utf-8')` 后比 bytes，实测非 ASCII token 正常回 401。

---

### N11 · 缺 `Vary: Accept-Encoding`（低）

响应体随 `Accept-Encoding` 不同而不同（gzip / 明文），就必须声明 `Vary`，
否则共享缓存（反代 / CDN）可能把 gzip 体发给不支持的客户端。
本服务自带 `no-store`，实际风险很低；属**正确性修正**而非漏洞。两处发送路径补齐。

---

### N12 · gzip 缓存可返回旧体（中）

缓存键只有 `(path, mtime(float), size)`，挡不住
"同长度改写 + `os.utime` 把 mtime 调回去"。
实测该情形下服务持续吐旧的压缩体（改动不落盘可见）。

**修复**：键扩为 `(path, ino, size, mtime_ns, ctime_ns)`。
`ctime` 由内核在写入时更新、`utime` 改不动它，所以把它放进键里就堵住这条路；
`ino` 再堵住"换成另一个文件但故意对齐时间与长度"。
修复后同一攻击实测返回新字节（`size same: True / mtime_ns same: True /
ctime changed: True → 服务返回新内容`）。

### N13 · 500 响应把本机绝对路径回显给客户端（中 · 我自己攻击时发现）

服务器层的掩码只覆盖了日志视图。对外的错误体仍是裸的 `str(e)`：

```
GET /api/real           →  {"error": "[Errno 13] Permission denied: '<验证用的临时目录>/web/real.redacted.json'"}

（原文里那一行是本机验证目录的真实绝对路径，这里**故意改写**：
报告本身也在交付包里，把 `release_check.py` 的构建机路径判据原样留在
prose 里，就是让文档匹配到自己的检查 —— 同 §6 讲字符类的理由。）
```

复现条件不是理论上的：把数据文件权限改坏（或在共享机器上放错属主），
以**非 root** 身份起服务，请求 `/api/real` 就拿到上面那一行。
这条与 `log_message` 里自己写的注释"**不回显文件系统路径**"直接矛盾 ——
注释承诺了一个代码没实现的性质，属于文档与实现的漂移，不是纸面问题：
部署目录名会告诉攻击者去哪找 `.private/`、`knowledge/events.jsonl`。

同一处 `traceback.print_exc()` 只在 stderr 落盘（不进 HTTP 响应），
所以它是本机信息泄露而非外带，保留（自用者需要看栈）。

**修复**：新增 `_safe_error(exc)`，回客户端前把 `HERE/WEB/WEB_REAL/父目录`
替换成 `<path>`，再用一条"至少两级"的绝对路径正则兜底。
刻意**不**匹配单段路径（`/etc/passwd` 里的 `/etc`），否则
`json.JSONDecodeError` 这类不含路径的正常错误会被误伤成不可读。
修复后同一攻击：

```
{"error": "[Errno 13] Permission denied: '<path>/real.redacted.json'"}
```

修复后响应体上 `grep -o "<临时目录>\|/ap[p]/"` 命中 **0**。
第一版还有个我自己写出来的缺陷：替换集合是无序的，父目录先被换掉会让
子路径匹配不上，输出 `<path><path>/real.redacted.json`（叠两层占位符）。
现在按长度**降序**替换。

正则成本另测：`'/'*20000`、`'/'+'a/'*20000`、无终止符深路径均在 2.5ms 内返回，
无灾难性回溯。

### N14 · 非回环监听 + 空口令 = 全量记忆导出无人看守（高 · 文档约定未被代码强制）

这条是本轮最"值"的一条，因为它的成因和 N7 一样：**约定写在文字里，
检查没写在代码里**。`_check_auth` 的 docstring 明写"本服务只应监听
127.0.0.1；若要放到局域网必须设 `DATABRAIN_TOKEN`"，然后：

```bash
DATABRAIN_HOST=0.0.0.0 python3 server.py      # 不设 token
```

实测（本机，无任何鉴权）：

| 请求 | 结果 |
|---|---|
| `/api/data` | **200，641 KB**（完整记忆导出：人物、情节、激素轨迹） |
| `/api/config` | 200，全部内部参数 |
| `/api/run?days=365&seed=1` | **200，1,184,499 B** —— 任何人可驱动重算 |
| `/api/real` | 200（发布版是脱敏的，自用版 FULL 模式下是未脱敏原文） |

`_check_auth` 里 `if not _AUTH_TOKEN: return True` 让"无口令"退化成"无鉴权"，
而绑定地址完全由环境变量决定 —— 三个环境变量的组合就能把整套记忆
暴露在局域网/公网。对一个人格模拟器来说这就是最坏情况。

**修复**：`_open_bind_without_token()` + `main()` 启动前置检查：
非回环地址（不在 `127.0.0.1/localhost/::1`）且 `DATABRAIN_TOKEN` 为空
→ **拒绝启动**，并列出三条出路（改回默认 / 设口令 / 显式知情放行）。
检查放在跑模拟**之前**，否则要等约 20 秒模拟跑完才报错，
终端里已经刷了一层无关输出。
知情口令是 `DATABRAIN_ALLOW_OPEN=1`（明确承担风险，比如前面已有反代）。
`README.md` 环境变量表补了这两行，并把"为什么值得拒绝启动"写进正文。

四种组合实测：

| 配置 | 行为 |
|---|---|
| `HOST=0.0.0.0`，无 token | 拒绝启动，rc=0，打印三选一 |
