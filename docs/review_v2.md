## 1. 对一轮结论的自我更正（这三条是我上一份报告的错误）

一轮写的是"事件先 tick 后刺激，所以『编码瞬间的身体状态』其实是事件前的状态"。
本轮用 spy 包住 `encoding_modulation` 记录它实际读到的激素值：

> 错在哪：我从"调用顺序"直接推"观察值顺序"，中间隔着一次赋值，没插桩就下了结论。

### A6 · **降级：设计级 → 输入面收敛**
一轮写"`prompt_suffix` 把语料文本拼进 LLM 提示词"。读完整函数体后更正：

## 2. 修复引入的新缺陷

### B12 · 清洗导致身份碰撞（**本轮最重要发现**）
一轮为修 B7（昵称含 `|` 打穿主题键）加了 `sanitize_subject()`，做法是**删字符**。
本轮探针直接构造 `测试/甲` 与 `测试甲`：两者清洗后同键，
引擎把它们当成同一个人 —— `contact_count` 混算、认定值共享、陪伴漂移互相污染。

实测（修复前）：

```
person buckets: ['测试甲']
contact counts: {'测试甲': (2, 0.866)}      ← 两个真人，一次接触被记到另一次头上
```

这是**修复制造的新缺陷**，而且踩的正是 B7 想保护的那个键结构 ——
一轮报告只看了"脏字符会不会破坏解析"，没看"清洗会不会损失身份"。

修复：凡清洗动过原名（含限长截断），附加原名 `zlib.crc32` 后缀；
本来就干净的名字（`莉莉` / `O'Brien` / `Tom & Jerry`）原样保留，可读性不受损。
选 crc32 而非内置 `hash()`：后者带进程级随机种子，会毁掉确定性。

```
person buckets: ['测试甲·70890ec6', '测试甲']   ← 修复后，2 个桶
同 seed 两次 export md5 仍完全一致（b697bd61bf…）
```

### N1 · 脱敏漏 `bucket_id`
`_redact()` 按字段名逐个映射人名，`events[].bucket_id`（值形如 `P:<人名>`）不在名单里。
带活体载荷的语料跑出来，脱敏版仍留着 `P:img" onload=alert(1) x`。

### N2 · 脱敏漏 `people_kept`，且根因是**别名表不同源**
`people_kept` 存的是语料原始名，而 `alias` 的键是**引擎清洗后**的名字。
两者不同源时 `alias.get(n, n)` 原样返回 —— 载荷名直接进发布文件。
修复：`people_kept` 也先过 `sanitize_subject()` 再映射。

### N3 · 脱敏漏在字典**键**上
`social_test._ambivalence_all` 以人名为 **key**。逐值替换碰不到 key。
修复：`_redact()` 收尾对整棵 JSON 树递归清洗，**键与值都过**。

### N4 · 对照载荷绕过脱敏 + 两份产物写同一对象
`build_compare()` 的 `real.people[].id` 直接取 `b.subject`（真实人名），
而 `main()` 里把**同一个 dict 对象**同时写给 `.private/compare.full.json`
和 `web/compare.redacted.json`，注释还写着"compare 只含聚合指标，无原文，两份一致"。
这句注释是错的：实测发布版里能查到原始人名。

同时暴露一个更隐蔽的问题：`real` 与 `compare` **各自生成别名表**，
`P3` 在两个文件里可能指不同的人 —— 前端两页交叉看就会读错人。
修复：`_alias_of()` 全工程唯一一张表，由 `main()` 算出后同时传给
`build_payload(..., alias=)` 与 `build_compare(..., alias=)`；两份产物各建各的副本。

跨文件一致性实测（按原始名回查）：

```
K.→P1  Momo→P2  奶奶→P3  室友→P4  老周→P5     ← real 与 compare 完全一致
```

### N5 · 配置静默降级（工程，非安全）
`load_people()` 只认 `{edges:[...], nodes:[...]}` 结构。
喂进扁平 `{名字:{weight:0.7}}` 时**静默返回 `{}`**，
而 `weight` 乘在事件强度上（`inten * (0.75 + 0.05*weight)`），
缺失即全体乘数落在 0.75，显著性够不到 0.42 的门槛 ——
现象是 `episodic` 恒为 0、社会化测试"负性记忆消退"变无数据，
而**日志一句提示都没有**。我本人在这上面踩了一次（第一次生成演示语料时）。

修复：兼容扁平写法；文件缺失/解析失败/结构不对一律 `stderr` 明确警告；
并把**量纲写进文档** —— `weight` 是 **0~10**（5 = 不缩放），不是 0~1。
这条不改变已有行为，但把"看起来在跑、其实整条记忆层是空的"变成会喊出来的故障。

### 3.4 关于 P-STEP（不算 FAIL，但要说清）
指数衰减用 `decay_factor(dt)` 一步算，与 `dt` 步连乘不等价，
所以**步长本身改变结果**：`dt=1` vs `dt=6` 时 cortisol/serotonin 差到 0.14~0.23
（cortisol 半衰期 1.5h 最敏感），人物效价差 0.005~0.048。
这不是可以"修掉"的 bug，是欧拉式离散化的固有性质。
一轮的 B10 说"真实/合成对照不是同尺度"，本轮的处理是**取消这个可比性宣称**
（见 C1），而不是假装把两边对齐。要真正消除，得改成解析解或自适应步长 —— 列为后续项。

## 5. 仍然开放的风险（未修，需知情）

1. **人名仍是可进提示词的任意字符串**（A6 残余）。
   `sanitize_subject()` 挡的是控制字符与结构破坏，挡不住昵称本身就叫
   "忽略以上指令"。真接 agent 时应把这段当不可信数据包在明确分隔符里，
   或用 ID 而非昵称入提示词。
2. **社会化测试是自指系统**（C3 未改）。8 项指标的合理区间由引擎自己标定，
   100 分不等于"像人"。README 已并列陈述，但这是结构性限制。
3. **关键词分类器仍是词表命中制**（C2 上限）。本轮实测 8 条正常中文：
   "今天还不错 哈哈"→`shared_joy`、"我妈住院了，这几天不太舒服"→`neutral`。
   所有建立在刺激标签上的涌现结论都只是假设。
   注：这些样本现在由 `tools/gen_figs.py` 自动打印进文档，不再由我口头挑选。
4. **配置是全局可变单例**（D2 部分修）。消融实验靠改全局再复原，
   同进程两个不同参数的 brain 仍无法共存。
5. **步长依赖**（§3.4）。
6. **上游 Ombre-Brain**（A5）：`mcp` 2.x 破坏 import（实测须 `mcp<2`）、
   HTTP 模式无鉴权、`safe_path` 与 databrain 一轮同款的 `startswith` 缺陷模式。
   桥接契约本身验证可用：只读 OB 桶、只写 `db_*`、OB 自有
   `valence/arousal/importance` 与检索/衰减不受影响。
